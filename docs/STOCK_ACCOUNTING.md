# สต็อก · โอนของระหว่างสาขา · กระทบยอด · กำไร-ขาดทุน

## ขึ้นระบบจริง (ทำตามลำดับ)

1. **สำรองฐานข้อมูลก่อน** (รัน workflow "Database Backup" ด้วยมือ หรือ dump จาก Railway)
2. เช็ก timezone ของ MySQL บน Railway ด้วย `SELECT @@global.time_zone, NOW(), UTC_TIMESTAMP();` ถ้า `NOW()` ตรงกับ `UTC_TIMESTAMP()` (คาดว่าเป็นแบบนี้) ไปขั้นต่อไปได้เลย ถ้าไม่ตรง ให้หยุดและแจ้งก่อน เพราะแอปจะบังคับทุก connection ให้ใช้ UTC
3. รัน `drizzle/add-stock-accounting.sql` ครั้งเดียวบน MySQL ของ Railway
   - สร้างตารางใหม่ 8 ตาราง เพิ่มคอลัมน์ `orders.costAmount` กับ `sales_channels.gpPercent`
   - ตั้ง GP ของ Grab / LINE MAN เริ่มต้นไว้ที่ 30% ให้แก้ตามสัญญาจริงที่ **ตั้งค่า → ช่องทางขาย**
   - สร้าง "คลังกลาง" และปิดการเบิกจากคลังของสาขาที่ชื่อมีคำว่า "ร้อยเอ็ด" (ตรวจได้ที่ **ตั้งค่า → สาขา**)
   - **ห้ามใช้ `pnpm db:push`** เพราะ snapshot ของ drizzle ไม่ตรงกับฐานข้อมูลจริง (มีไฟล์ add-*.sql ที่รันด้วยมือมาก่อน)
4. Deploy โค้ด
5. **ทุกเครื่องต้องใส่ PIN ใหม่หนึ่งครั้ง** (ระบบเปลี่ยนมาใช้ session จากเซิร์ฟเวอร์)
6. ผู้จัดการตั้งค่าเริ่มต้นที่หน้า **สต็อก**
   - แท็บ **วัตถุดิบ**: เพิ่มวัตถุดิบ หน่วย ต้นทุนต่อหน่วย และจุดสั่งซื้อ
   - แท็บ **สูตรเมนู**: ใส่ปริมาณต่อ 1 แก้ว (แยกตามขนาดได้) และตัวเลือกที่ใช้วัตถุดิบ เช่น เพิ่มช็อต หรือนมโอ๊ต
   - แท็บ **นับสต็อก**: นับของที่มีอยู่จริงในคลังกลางและแต่ละสาขา เพื่อตั้งยอดเริ่มต้น
   - ถ้ามีคนประจำคลัง ให้สร้างบัญชีพนักงานที่ผูกกับ "คลังกลาง" เมื่อเข้าระบบจะเปิดมาที่หน้าสต็อกเลย

## ระบบทำงานอย่างไร

- **คลังกลาง**:
  - ซื้อของเข้าคลังเป็นหลัก (รับของเข้า โดยเลือกคลังกลาง)
  - หน้าบ้านขอนแก่นกับศรีจันทร์หยิบของเองแล้วบันทึกที่แท็บ **เบิกจากคลัง** ของย้ายเข้าสต็อกสาขาทันที คืนของเข้าคลังได้จากแท็บเดียวกัน
  - คนประจำคลังบันทึกแทนสาขาได้
  - ถ้าเบิกเกินกว่าที่ระบบมี ยังบันทึกได้ (เพราะหยิบของไปแล้วจริง) แต่ระบบจะเตือนว่าน่าจะลืมบันทึกรับของเข้าคลัง
  - คลังกลางไม่มีหน้าขาย ไม่อยู่ในรายงานยอดขาย แต่ของเสียและส่วนต่างการนับของคลังยังนับในกำไร-ขาดทุน
- **ร้อยเอ็ด**: สั่งของเองและรับเข้าสาขาตัวเอง ไม่เห็นแท็บเบิกจากคลัง

- **ขาย**: ระบบตัดวัตถุดิบตามสูตรของสาขาที่ขาย และบันทึกต้นทุนของบิลไว้ ณ เวลาขาย (อยู่ใน transaction เดียวกับบิล) เมนูที่ยังไม่มีสูตรใช้ "ต้นทุน" ในหน้าจัดการเมนูแทน และไม่ตัดสต็อก
- **ยกเลิกบิล**: คืนวัตถุดิบด้วยจำนวนและต้นทุนเดิม ยกเลิกซ้ำไม่คืนซ้ำ
- **รับของเข้า**: คำนวณต้นทุนเฉลี่ยต่อหน่วยใหม่ (moving average รวมทุกสาขา)
- **โอนระหว่างสาขา**: ของออกจากต้นทางทันทีที่กดส่ง และเข้าปลายทางเมื่อปลายทางกดรับ ส่วนที่ได้รับไม่ครบบันทึกเป็นของเสียของปลายทาง ยกเลิกได้ก่อนปลายทางรับ
- **นับสต็อก**: ปรับยอดให้ตรงกับที่นับได้ ส่วนต่างคิดเป็นมูลค่า (ของขาดเป็นค่าใช้จ่าย)
- **กระทบยอด** (รายสาขา รายวัน):
  - โอนเข้าบัญชีร้าน = บิลหน้าร้านที่จ่ายด้วยการโอน
  - Grab / LINE MAN = ยอดขายของช่องทาง − GP
  - คลาดเคลื่อนไม่เกิน 1 บาทถือว่าตรง
- **กำไร-ขาดทุน**: ยอดขาย − VAT − GP (ใช้ค่าจริงถ้ากระทบยอดแล้ว ไม่งั้นประมาณจาก %) − ต้นทุนวัตถุดิบ − ของเสีย ± ส่วนต่างการนับ ± ส่วนต่างกระทบยอด ยังไม่รวมค่าเช่า ค่าแรง และค่าน้ำไฟ
- วันทางบัญชีปิดตอนเที่ยงคืนเวลาไทย

## สิทธิ์ (เซิร์ฟเวอร์ตรวจทุกคำขอ)

- ทุก API ยกเว้นหน้าเข้าสู่ระบบ ต้องมี token จากการใส่ PIN (header `x-staff-token`, อายุ 30 วัน) ระบบอ่านสิทธิ์และสาขาจากฐานข้อมูลทุกครั้ง
- คนที่ผูกกับสาขาถูกล็อกไว้ที่สาขาตัวเองเสมอ ทั้งบิล รายงาน สต็อก และบัญชี แอดมินดูได้ทุกสาขา
- พนักงานใช้หน้าขาย แก้ราคา และรับของ / นับ / ของเสีย / โอนของสาขาตัวเองได้
- ผู้จัดการทำได้เพิ่ม: ยกเลิกบิลจากรายงาน, เมนู, สูตร, บัญชี, จัดการพนักงาน (ยกเว้นบัญชีแอดมิน)
- ระบบไม่ส่ง PIN ออกจากเซิร์ฟเวอร์ ใส่ PIN ผิด 5 ครั้งล็อก 5 นาที
